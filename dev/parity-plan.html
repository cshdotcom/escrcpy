escrcpy-Next × 官方 v3.3.1 功能对齐与超越总计划 ​

本文档是本任务规格的唯一权威来源（2026-11-25 用户提供并确认）。后续所有会话（含定时续做）必须以本文 + parity-progress.md 为准，用 git tag / git log 核对真实进度，不信任何口头声称。 基线：v3.10.2（main = b683ede8）。官方对照对象：官方 Escrcpy-3.3.1 付费闭源全功能二进制。

0. 铁律（违反任意一条 = 任务失败） ​

  • 仓库 cshdotcom/escrcpy-Next，分支 main；允许 feat/* 分支，合并前必须 build + 图标门禁 + e2e 全绿。
  • 增量交付：每完成一个模块 → commit → 打 tag → push → 触发 CI → 验证三平台资产可下载。沙箱随时被回收，未推送的代码等于丢失；单阶段内的中途成果用 snapshot/* tag 保护。
  • 禁止"文案在、功能没做"：每个功能必须同时具备 ①UI 入口 ②IPC/HTTP 接口 ③执行路径 ④e2e 断言。只加 locale key、只加常量、只加按钮都算未完成。
  • 不许回退已有能力：v3.7.0–v3.10.2 已有的（EIO 守卫、配置持久化、离线自愈、自动重连、错误隔离、上下文压缩、群控广播、多设备 AI、OpenCV 识图前置、网页三页签、镜像 WebCodecs、工作流画布、多屏协同、单 data 消费者架构…）一个都不许丢，改到就补 e2e。
  • 代码注释英文；UI 文案走 i18n（en-US / zh-CN / zh-TW 三份必须同步，pnpm lang-sync 校验）。
  • 本地环境与 CI 对齐：corepack prepare pnpm@12.21.0 --activate + pnpm install --frozen-lockfile + pnpm exec turbo build + node scripts/check-icons.js。lockfile 是 pnpm 12 双文档格式，不许剥离。

1. 官方基准：v3.3.1 付费闭源功能清单（验收对照表） ​

官方 deb → resources/app.asar（标准 asar）。官方 locale（zh-CN.json，1305 条）是功能点权威清单；付费页面文案内嵌在页面 bundle 中。公开源码只有 control / explorer / terminal 三页；automation / mirror / copilot 是闭源付费模块，只能逆向二进制，不是比对源码。

1.2 官方「群控镜像」（mirror 页，31 条文案 + 通道表） ​

  • 一个镜像窗口承载 N 台设备（mirror.devices），顶部「打开所有设备」。
  • 手势广播：点击/滑动/文字输入并行下发设备组（BROADCAST_TOUCH_EVENT / BROADCAST_KEY_CODE / BROADCAST_SCROLL）。
  • 首次使用三步操作指引（点击、滑动、输入 → 多台同步），可「不再提示」。
  • 置顶/取消置顶、全屏/退出全屏、输入条（Enter 发送、关闭）、返回/主页/最近任务快捷键、连接中/已断开/重新连接。
  • 技术底座（已验证）：主进程 scrcpy 协议栈、WebCodecs optimizeForLatency、CSD 拼接、丢帧保护、konva 键位画布、scrcpy:* IPC 通道表。

1.3 官方设备控制栏缺口（device.control，128 条中 14 条未引用） ​

多屏协同细节文案、启动应用目标窗口选择（当前窗口=内嵌镜像 / 主显示器 + 启动设置 + 分身用户提示）、音量三项独立命名、截图成功"去查看"、文件管理器全选/反选/取消全选/重命名成功/上传进度/下载失败/推送失败、gnirehtet 停止成功。

1.4 官方 AI（copilot） ​

闭源，走 api.moark.com 网关。我们自研版更完整（多供应商、工具循环、定时任务、上下文压缩、多设备），不做 1:1 对照，但必须不弱于官方：多轮工具调用、视觉回传、会话续聊、用量与错误可见。

2. 核验方法（每个会话必须重跑，禁止采信既有结论） ​

  1. 文案落地率（hyphen-aware 版本，见 scripts/ 与 parity-report）：
    • 基线（2026-11-25 实测）：automation 170 总 / 30 引用 / 140 未引用；mirror 31 / 5 / 26；device.control 128 / 114 / 14。
    • 目标：automation ≥95% 引用、mirror ≥90%、device.control ≥95%，且每条引用对应真实 UI。
  2. 执行器分支清单：grep -nE "case '" desktop/electron/modules/tasks/helpers/executor.js，与 1.1 对表。
    • 基线（实测 18 种）：broadcast_input_text / broadcast_key / broadcast_screenshot / broadcast_tap / get_device_info / get_ui_layout / http / input_text / key / list_devices / match_image / notify / open_app / screenshot / shell / swipe / tap / wait_image。
    • 缺：wait、install、record、loop、condition 步骤类型 + launch 强停 + 步骤级 delayBefore / loopCount / randomRange。
  3. UI 入口清单：每个功能在 desktop/pages/** 有组件与交互，不能只出现在常量文件。
  4. 手动跑一遍：本地 build + e2e（fake adb 双设备），逐功能点验证（官方要求"实际可用"而不是"应该能用"）。

3. 应用端待补功能（优先级 + 验收口径） ​

P0-A 自动化脚本工作台（v3.11.1） ​

新页面 desktop/pages/automation/（独立窗口，注册 vite input）。数据模型 scripts: [{id, deviceId, name, steps[], variables[], createdAt, updatedAt}] 落 electron-store。布局：左脚本列表 / 中步骤列表（拖拽排序、复制、前后插入、删除、高级折叠）/ 右步骤表单 / 底执行日志。执行引擎：单步/选中/全量/暂停/继续/停止；状态机 idle→running⇄paused→stopped；同脚本不并发；切换先停。步骤统一字段 name/type/delayBefore/loopCount/randomRange/imageMatch/target。导入导出 JSON（导入前确认替换）。 验收：假设备跑「启动 App→点击→输入→截图」四步脚本，单步、暂停恢复、日志逐条、导出再导入一致；e2e 覆盖。

P0-B 补齐步骤类型（v3.11.2） ​

install（adb install -r + 可选先卸载）、record（screenrecord，屏幕/摄像头、时长、目录）、launch（包名/已装 App + 强停）、loop（子步骤循环）、condition（图像存在/设备在线/变量比较）、wait、command（shell 自动设备前缀）。 验收：每类 ≥1 条 e2e + executor 单测；loopCount/randomRange 生效可观测（日志打实际坐标与延时）。

P1-A 智能拾取（v3.11.3） ​

实时截图 → 画布拖拽裁剪存模板 + 单击取坐标 + 拖拽画轨迹；重新裁剪、预览、失败给可读错误。 验收：裁剪模板直接喂 imageMatch 匹配成功。

P1-B 魔法变量 + 批量执行（v3.11.3） ​

{var} 解析（步骤所有文本字段）、自定义变量 CRUD + 校验、内置变量 date/deviceId/stepIndex/timestamp；批量执行表格（一行一设备 + 变量列）并行下发、终止。 验收：同一脚本 2 台设备灌不同变量，日志正确互不串。

P1-C 官方模板库（v3.11.3） ​

打开 App / 账号登录 / 批量截图 / 微信发消息 四套模板，「从模板创建」。

P2 官方级群控与多屏（v3.13.0） ​

镜像窗口多设备同屏（N 宫格）、主控手势广播全组、「打开所有设备」、三步首用指引；多屏协同 ROM 检测 + 兼容提示；内嵌镜像内启动 App（「在当前窗口打开」）。

4. 超越官方：必须新增（v3.12.0 起） ​

  1. 自然语言生成脚本（一句话 → 步骤草案，复用 Copilot 供应商栈，可编辑可 dry-run）
  2. UI 操作录制成脚本（镜像窗口操作录制为步骤，一键转脚本）
  3. 失败诊断与断点续跑（原因分类：设备离线/图像未匹配/权限/超时 + 建议；从失败步骤续跑）
  4. 脚本版本历史（保存留版本，可 diff、可回滚）
  5. dry-run 预检（设备在线、APK 存在、模板存在、变量齐全，列风险项）
  6. 多设备并行执行 + 每设备独立变量 + 汇总报表（成功/失败/耗时，导出 CSV）
  7. 条件分支可视化（画布 if/else 分叉）
  8. 模板分享码（导出短码/JSON 可导入）
  9. 执行产物归档（截图/录屏按「脚本-设备-时间」归档，可对比两次运行差异）
  10. AI 复盘（批量执行结束自动总结失败原因与建议，可关）

5. 网页端（目标：桌面端 90% 能力在浏览器可用） ​

现状：对话/自动任务/镜像三个页签（18 个 /api/ 端点）。要补：

  1. 任务/工作流/脚本完整 CRUD（新建、编辑、复制、删除、启停、cron、上下文策略）
  2. 自动化脚本工作台（步骤编辑、单步/暂停/继续、日志、导入导出、变量）
  3. 群控面板（多选设备广播点击/滑动/文字/按键、批量截图、批量装 APK、日志）
  4. 镜像增强（多设备同屏、全屏、键位映射在线编辑、剪贴板、快捷按键）
  5. 对话增强（文件/图片上传、会话重命名/删除/搜索/导出、消息重发/编辑、工具卡片展开）
  6. 运行历史详情（每步耗时、输入输出、失败原因、日志下载）
  7. 供应商设置（baseUrl/model/apiKey 可改，apiKey 不回显明文）
  8. 移动端适配（触控、软键盘避让、横屏镜像、单手布局）
  9. 实时性（SSE 断线重连 + 心跳；镜像 WS 重连提示）
  10. 安全（bcrypt 密码、短时 token、失败限流 5 次/分钟、只读模式、可选 HTTPS/仅内网）
  11. 空态/骨架/Toast/深色/i18n（跟随浏览器） 验收：手机浏览器完成「新建脚本 → 跑 2 台设备 → 看日志 → 截图归档」全流程。

6. 人性化清单（两端统一验收） ​

首用四步向导（可跳过）；空列表给「下一步」引导；危险操作二次确认（删脚本/卸载/批量执行/格式化类）；撤销重做（步骤编辑、脚本删除 30 秒恢复）；拖拽排序、复制、批量选择；错误一律"人话+原因+建议+一键重试"；长任务进度条 + 预计剩余 + 可中止；快捷键面板（可查可改）+ WASD 提示；三语言 + 无障碍（键盘可达、aria-label）+ 高对比；日志一键复制/导出。

8. 历史坑（踩过就会失败） ​

  1. pnpm 12.21.0 lockfile 双文档格式，剥离第一段 = CI frozen-lockfile 必挂；本地也用 pnpm 12。
  2. 新页面必须注册 vite build input，否则开发正常、打包白窗（group-control 踩过；mirror 页已一并注册）。
  3. solar 图标名先跑 node scripts/check-icons.js（曾 3 个 + 1 个 chat 图标导致 build 门禁 5 连红）。
  4. rolldown：模块级常量被 DCE 误删（用 export 保护）；re-export 链符号重命名碰撞（显式导入、不用匿名类）。
  5. scrcpy：视频包 pts 大端；视频 socket 只能挂一个 data 消费者（多监听瓜分字节流错帧）。
  6. adbkit：v1 shell 输出被真实 adb LF→CRLF；screencap 实际是 echo && screencap -p。
  7. electron-store 嵌套路径（copilot.settings 是路径不是扁平 key）。
  8. e2e i18n：生产构建 process.resourcesPath 指向内置目录，按钮 title 是原始 key，断言兼容 key + 中英文。
  9. 改名残留：deviceId→deviceIds 后必须全局 grep（遗漏 = ReferenceError + 消息静默不发）。
  10. 大文件下载必须校验 sha256（官方 deb 真实大小 123,461,804 字节）。
  11. 沙箱会回收后台进程与工作区：安装用 setsid 脱离 + 日志轮询；所有成果及时 push；lockfile/工作成果在 /home/z/my-project/ 内。
  12. Mac 构建机排队超时会复发（v3.9.0、v3.10.2 均遇），按既有 rerun 策略处理。
